# twanga-app

TWANGA's Tauri desktop shell. Wraps the shared `frontend/web/` bundle
(pluggable renderer system, Web Audio capture, twanga-web WASM
bindings) in a native window on Windows / macOS / Linux. iOS / Android
arrive via Tauri Mobile once Tauri Mobile lands as stable.

The desktop story is "one frontend, shipped two ways": the exact same
HTML/JS/WASM bundle that loads in a browser at the deployed URL also
loads inside this app's webview. No separate native UI. The only thing
this crate does is open the window and (eventually) expose Tauri
commands for things the browser sandbox can't do — lower-latency native
audio capture via CPAL, filesystem access for `~/.config/twanga/`, etc.

Tauri 2's recommended `lib.rs` + `main.rs` split is in place so the same
`run()` entry point will work for the future mobile build without
refactor — `mobile_entry_point` macros wrap the lib; the desktop bin
calls into it.

## Local development

You need [Rust](https://rustup.rs) **and** the platform's Tauri prerequisites:

- **Windows**: WebView2 (preinstalled on Windows 10/11; download from
  [Microsoft](https://developer.microsoft.com/microsoft-edge/webview2/)
  if needed).
- **macOS**: nothing extra — WebKit is system-provided.
- **Linux**: `libwebkit2gtk-4.1-dev`, `libssl-dev`,
  `libayatana-appindicator3-dev`, `librsvg2-dev`, `libsoup-3.0-dev`,
  `build-essential`. On Debian/Ubuntu:
  ```bash
  sudo apt install -y libwebkit2gtk-4.1-dev libssl-dev \
      libayatana-appindicator3-dev librsvg2-dev libsoup-3.0-dev build-essential
  ```

Plus the tooling for the WASM bridge the webview consumes:

```bash
cargo install tauri-cli --version '^2'
cargo install wasm-bindgen-cli --version 0.2.121   # if not already installed
rustup target add wasm32-unknown-unknown
```

Once that's done, the dev loop is:

```bash
# 1. Build the WASM bindings the frontend consumes
cargo build --target wasm32-unknown-unknown -p twanga-web --release
wasm-bindgen --target web --out-dir frontend/web/pkg \
    target/wasm32-unknown-unknown/release/twanga_web.wasm

# 2. Copy the bundled alphaTex examples into the site root. The browser
#    library fetches them from `assets/examples/` relative to the bundle;
#    the canonical files live at the repo root so the CLI can use them
#    too. `frontend/web/assets/` is gitignored — same pattern as
#    `frontend/web/pkg/`. CI's pages.yml workflow runs the same copy.
mkdir -p frontend/web/assets && cp -r assets/examples frontend/web/assets/
# Windows PowerShell equivalent (run from repo root):
#   New-Item -ItemType Directory -Force frontend/web/assets | Out-Null
#   Copy-Item -Recurse -Force assets/examples frontend/web/assets/

# 3. Launch the Tauri shell pointing at frontend/web/
cargo tauri dev
```

`cargo tauri dev` opens a native window with `app.html` as the entry
point. Hot reload of the frontend works for plain HTML/JS edits;
WASM changes need step 1 to rerun.

For a release build:

```bash
cargo tauri build
```

Produces platform-native installers (`.msi` on Windows, `.dmg` on macOS,
`.deb` / `.AppImage` on Linux) under `target/release/bundle/`.

## Layout

- `Cargo.toml` — workspace member with `tauri` + `tauri-build` deps.
- `tauri.conf.json` — points `frontendDist` at `../../frontend/web` and
  opens `app.html` as the main window URL. CSP is `null` for now (will
  tighten when we know what external resources, if any, the frontend
  loads beyond local files).
- `build.rs` — runs `tauri_build::build()` to emit the platform
  manifests (Windows resource file, macOS Info.plist, etc.).
- `src/lib.rs` — `pub fn run()` containing the `tauri::Builder` invocation.
- `src/main.rs` — desktop entry point; calls `twanga_app::run()`.
- `icons/` — generated by `cargo tauri icon assets/logo.png` from the
  workspace logo. Includes Windows `.ico`, macOS `.icns`, plus the
  per-platform PNG sizes.

## Tauri commands

None exposed yet — the frontend is currently self-sufficient (Web Audio
for capture, WASM for DSP). When we need to drop into native code (e.g.
the CPAL backend for sub-20ms input latency on desktop, or filesystem
access to read `~/.config/twanga/tunings.toml`), commands go in
[`src/lib.rs`](src/lib.rs) and get registered with the builder.

- **Depends on**: `twanga-core` (today), `tauri`, `tauri-build`. Will add
  `twanga-audio` / `twanga-dsp` once native commands need them.
- **Used by**: nothing inside the workspace (top of the dependency graph
  on the desktop side; the future Tauri Mobile builds reuse the same
  `lib.rs` entry point).

See [the workspace README](../../README.md) for project context.
